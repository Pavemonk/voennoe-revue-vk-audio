# Радио КП — Прямой эфир (0.4.0)

Минималистичный Android-плеер для прослушивания эфира Радио КП без вывода и декодирования видеодорожки.

## Источники

1. **VK Видео** — основной источник. Приложение открывает `https://vkvideo.ru/@radiokp/lives`, обнаруживает HLS URL в ответе `video.getVideoDiscover`, передаёт ссылку в Media3 и уничтожает WebView после нахождения потока.
2. **RuTube** — резервный источник. Приложение открывает официальный канал `https://rutube.ru/u/radiokp/`, отслеживает запросы `api/play/options`, извлекает HLS только когда ответ помечен `is_live=true`. Архивные записи не должны приниматься за живой эфир. Для этого используется неофициальная, наблюдаемая структура API; RuTube может её изменить.
3. **Радио КП** — последний резерв. Используются опубликованные на официальном сайте московские MP3-потоки 32 / 64 / 128 кбит/с: `kpradio32.streamr.ru`, `kpradio64.streamr.ru`, `kpradio128.streamr.ru`. Официальная страница: https://radiokp.ru/about. Эти ссылки могут перенаправлять на `kpradio.hostingradio.ru:8000`.

## Качество аудио

- VK и RuTube настраиваются **раздельно**. Ограничение задаётся через Media3 для аудиодорожек HLS. Оно работает, если платформа публикует несколько аудиодорожек/вариантов. Приложение не может перекодировать исходный поток на телефоне.
- Радио КП: выбор переключает реальные московские адреса 32 / 64 / 128 кбит/с. По умолчанию 64 кбит/с.
- Для VK/RuTube при единственном варианте потока настройка может не уменьшить фактический трафик; если в HLS звук и видео объединены в одних сегментах, отключение декодирования видео само по себе не гарантирует, что видеоданные не скачиваются.
- Для видеоисточников по умолчанию установлен предел 64 кбит/с. Это ограничение выбора доступной аудиодорожки, а не перекодирование потока на телефоне.

## Возможности

- Автозапуск основного источника VK при открытии приложения (включён по умолчанию).
- Раздельные настройки максимального аудиобитрейта для VK и RuTube, отдельный выбор реального радио-потока 32/64/128 кбит/с.
- Автоматический переход VK → RuTube → Радио КП при ошибке воспроизведения или таймауте обнаружения трансляции.
- Ручной выбор / переключение источников предыдущий/следующий. Во время поиска страница платформы скрыта; при необходимости её можно временно открыть кнопкой «Показать страницу VK/RuTube».
- Старт, пауза, продолжение и стоп.
- Раздельные настройки качества VK и RuTube; отдельный выбор реального битрейта третьего источника Радио КП; автозапуск и авто-переключение.
- Фоновое воспроизведение нативным Media3 в foreground service и управление из уведомления.
- Видеодорожка отключена через Media3 TrackSelector. Временный WebView используется только на этапе обнаружения трансляции, по умолчанию он скрыт и не занимает место на экране; кнопку «Показать страницу» можно нажать для ручного выбора LIVE. Изображения не загружаются, найденный поток передаётся нативному плееру, после чего WebView полностью уничтожается.
- Для радио разрешён cleartext только на четырёх доменах, необходимых для официальных потоков и редиректа; остальной cleartext заблокирован.

## Ограничения и статус проверки

Это экспериментальная интеграция с платформенными видеосервисами. Внутренние механизмы VK и RuTube не являются стабильными публичными API и могут меняться. Поток VK уже был воспроизведён пользователем в предыдущей версии. Интеграция RuTube и автоматическое переключение источников ещё не проверялись на действующей трансляции. Вне эфира приложение закономерно не сможет проверить эти два видеоканала.

В режиме радио возможен известный обрыв примерно через 40 минут, о котором сообщил пользователь. Плеер делает до двух повторных подключений к выбранному потоку с короткой задержкой. Поэтому радио оставлено третьим резервом, а не основным источником.

Прогресс в интерфейсе показывает состояние соединения/live и время прослушивания, а не позицию перемотки: прямой эфир не имеет надёжной фиксированной длительности или доступной перемотки в нативном аудиопотоке.

## Сборка через GitHub Actions (без Android Studio на ПК)

1. Загрузите содержимое проекта в корень существующего GitHub-репозитория, сохранив пути файлов и папку `.github`.
2. Commit changes запускает workflow автоматически. Вкладка **Actions** показывает статус.
3. При успешном запуске скачайте артефакт `radio-kp-live-apk` и извлеките `app-debug.apk`.

Workflow скачивает Gradle напрямую и не использует `gradlew`, поскольку в zip не вкладывается бинарный Gradle Wrapper JAR.

## Установка обновления

Application ID остаётся `ru.radiokp.voennoerevue`, versionCode увеличен до 4. Если Android не разрешит установить поверх предыдущей debug-сборки из-за отличающейся подписи, потребуется удалить старое приложение и установить новый APK. При удалении локальные настройки будут сброшены.


## Изменения версии 0.4.0

- Битрейт VK и RuTube хранится и настраивается отдельно.
- Разбор ответа RuTube учитывает массив `live_streams.hls[].url` и по-прежнему требует явный флаг `is_live=true`, чтобы не подключаться к архивной записи.
- Для резервного радио предусмотрено до двух повторных подключений при каждом обрыве MP3-сессии; после успешного подключения счётчик повторов сбрасывается.
- `versionCode=4`, `versionName=0.4.0`.
